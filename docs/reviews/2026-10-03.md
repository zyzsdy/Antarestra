# Antarestra 整体代码评审（2026-10-03）

审查基线：`8c5ddbe`。本次覆盖工作区包清单和依赖图、启动与插件生命周期、AI 运行、身份权限、HTTP / IM 入口、存储与资源边界，以及开发和功能文档。以下行号指向该基线的产品代码；本次提交修改文档，没有修复下列运行时代码问题。

结论：**插件与 AI 后端分离的主方向成立，仓内扩展便利；HTTP/WebUI 耦合、授权一致性和第三方发布流程仍有明显缺口。应先修复本地用户管理提权与网页工具出站边界，再推进公开多租户部署。**

## 已确认问题

P1 表示应优先修复的权限或安全问题，P2 表示影响正确性、可组合性和维护效率的问题。每项说明触发条件、代码位置、证据与建议；设计取舍和未实测的容量风险在后文单列。

### 1. [P1] 创建本地账号绕过角色授予上限

位置：[auth-local/src/index.ts，第 249–260 行](../../plugins/implementations/auth-local/src/index.ts#L249-L260)，以及同文件第 102–108 行的 `grantRole()` 调用。

创建账号接口要求 `identity.local.manage` 和 `authz.binding.manage`，但只检查目标角色是否存在、启用，没有像 RBAC 角色绑定接口那样检查目标权限是否超出操作者权限。拥有这两个受委派权限的用户可以创建权限高于自己的账号，破坏“管理员没有隐式全权限”的设计。

**证据：**真实 Cordis、SQLite 内存库和临时 HTTP 端口下，同一受限操作者在标准角色绑定接口获得 403，而创建高权限账号接口返回 201；新账号完成初始密码修改后具有 `admin.system.restart`。没有访问现有账号或外部服务。

**建议：**把可授予角色的校验收敛为 RBAC 服务方法，创建账号、修改绑定、批量导入共用；在同一事务中重新检查操作者及角色权限，增加低权限管理员不能创建高权限账号的回归测试。

### 2. [P1] 重置密码可以接管更高权限账号

位置：[auth-local/src/index.ts，第 278–305 行](../../plugins/implementations/auth-local/src/index.ts#L278-L305)。

接口仅检查 `identity.local.manage`，随后修改目标密码、撤销会话并向操作者返回可登录的初始密码，没有比较目标与操作者权限，也没有复用禁用账号接口已有的管理员保护。因此仅有本地用户管理权限的受限管理员可以接管系统管理员。强制首次改密码不能消除该问题。

**证据：**隔离 SQLite 实验中，受限操作者重置高权限账号返回 200，随后能登录该测试账号并完成密码修改。原有保护账号禁用的测试不能覆盖这条路径。

**建议：**为密码重置设立明确的目标权限限制，保护自身及更高权限账号，并对敏感目标要求相应授权或二次认证；回归测试同时覆盖默认角色和额外授权，避免只判断角色名。

### 3. [P1] 网页工具缺少服务端出站网络边界

位置：[common.ts，第 37–47 行](../../plugins/features/web-tools/src/common.ts#L37-L47)、[browser.ts，第 239–253 行](../../plugins/features/web-tools/src/browser.ts#L239-L253)、[PDF 获取，第 182–183 行](../../plugins/features/web-tools/src/browser.ts#L182-L183)。默认助理的全部工具选择见 [ai-agents/service.ts，第 115 行](../../plugins/features/ai-agents/src/service.ts#L115)。

URL 校验只限制 HTTP(S) 和嵌入凭据，浏览器直接导航，PDF 请求自动跟随重定向。启用网页工具并将其授权给普通 AI 用户后，该用户可通过服务器浏览器/HTTP 访问回环和内网资源；若部署网络允许，还可能访问链路本地服务。浏览器 Cookie 按会话隔离不解决服务端请求伪造（SSRF）。

**证据：**本次开启真实 Chromium 测试，现有 `web-tools.test.ts` 的本地网页、交互与 PDF 内容断言通过，确认 `127.0.0.1` 可读。未探测用户内网或云元数据服务；后两者的影响基于相同无过滤网络路径推导。

**建议：**制定统一出站策略，覆盖 URL、DNS 解析后的地址、每次重定向、子资源、iframe 与新页面，并明确处理 IPv6、地址变体和 DNS 重绑定。默认拒绝非公网目的地；确有内网需求时提供显式受控配置。浏览器与 HTTP 请求应共享策略，部署层的受限出站网络可提供额外保护。

### 4. [P2] 身份撤销不能阻止活动 Run 的后续工具执行

位置：[runtime.ts，第 82–101 行](../../plugins/definitions/ai/src/runtime.ts#L82-L101)、[模型请求，第 289 行](../../plugins/definitions/ai/src/runtime.ts#L289)、[工具批次，第 735 行](../../plugins/definitions/ai/src/runtime.ts#L735)。

`active()` 检查取消信号和绑定注册项是否仍有效，却不重新验证请求身份及权限。开始 Run 后注销、撤销身份或变更授权，不保证下一次模型请求和工具执行被阻止。部分内置资源工具自行调用 `authorizeRunContext()`，网页工具与第三方工具没有统一保障。

**证据：**隔离运行在首次模型请求等待期间撤销 RequestSource 身份；`ctx.ai.verify(access)` 已返回 401，恢复模拟模型后仍执行一次工具并发出第二次模型请求，最终得到 `toolExecuted: true`、`modelCalls: 2`、`status: completed`。

**建议：**核心在模型请求和每次实际工具执行前重新验证授权；验证失败取消 Run。测试在运行中撤销会话、角色、空间成员及后台身份。Run 配置快照应冻结能力选择，而非永久冻结授权有效性。

### 5. [P2] WebUI 生命周期控制了后台模型与助理能力

位置：[ai-provider/index.ts，第 18–25 行](../../plugins/features/ai-provider/src/index.ts#L18-L25)、[ai-agents/index.ts，第 17–24 行](../../plugins/features/ai-agents/src/index.ts#L17-L24)。

两个插件将 `webui` 作为顶层必需依赖，数据库服务、模型注册和页面注册位于同一生命周期。维护、停用或加载失败的网页壳会撤销后台模型和助理，使 IM 和定时任务也受影响。

**证据：**真实 SQLite 内存库实验中，无 WebUI 时两个 Fiber 为等待状态且服务不存在；加载 WebUI 后服务出现；卸载 WebUI 后服务再次消失。

**建议：**后台服务独立初始化，页面通过可选 `ctx.inject(['webui'], ...)` 子插件注册；HTTP 接口也可单独归属其依赖。可复用现有其他插件中局部注入的模式，无需更换插件运行时。

**修复记录（2026-10-04）：**两个插件的后台初始化仅要求数据库、AI 与 RBAC，页面和 HTTP 接口分别由 `webui`、`server` 局部注入注册。新增 `tests/integration/ai-management-lifecycle.test.ts`，覆盖无 WebUI 初始化与 SQLite 配置恢复、WebUI 反复加载和卸载期间活动运行保持有效，以及后台插件独立卸载、AI 依赖恢复后的注册与资源清理。此修复针对本项，AI/RBAC 核心自身的 HTTP 依赖仍保留。

### 6. [P2] Schema 文件缓存导致面板与运行时使用不同配置契约

位置：[plugin-sdk/schema.ts，第 18–25 行](../../packages/plugin-sdk/src/schema.ts#L18-L25)，对照 [config-loader/catalog.ts](../../packages/config-loader/src/catalog.ts)。

SDK 按 URL 永久缓存解析后的 JSON Schema，插件重载不使缓存失效；配置管理器另行读取磁盘的新 Schema。第三方插件更新 Schema 并重载后，面板可能接受新字段，而插件内部 `schemaConfig()` 仍按旧定义拒绝。

**证据：**临时目录同一路径的 Schema 从允许 `before` 改为允许 `after` 后，第二次校验仍按旧 Schema 返回 `additionalProperties` 错误。

**建议：**取消文件永久缓存，或依据文件版本/mtime 管理失效；面板预校验与插件初始化使用同一份有版本的 Schema。覆盖 Schema 文件变更、插件重载和包更新场景。

### 7. [P2] 模块导入失败丢失可诊断原因

位置：[config-loader/manager.ts，第 185–188 行](../../packages/config-loader/src/manager.ts#L185-L188)。

插件导入及配置预处理异常被统一替换成泛化提示，且没有写入诊断日志。导入在 Fiber 创建前失败时，Cordis 无法补充日志，第三方开发者无法分辨缺依赖、错误导出、配置校验或缺少环境变量。

**证据：**隔离 resolver 抛出固定测试错误后，面板仅显示通用失败，注册的日志输出器收到空数组。

**建议：**记录脱敏的阶段、实例、错误码和诊断编号，保留受控的内部原因链。浏览器保持脱敏，不直接公开任意异常全文；环境变量值和插件抛出的凭据不得进入日志。

### 8. [P2] 模型输出截断被报告为完整成功

位置：[ai-agent-core/index.ts，第 125–126 行](../../plugins/implementations/ai-agent-core/src/index.ts#L125-L126)、[runtime.ts，第 217 行](../../plugins/definitions/ai/src/runtime.ts#L217)。

执行后端把没有工具调用的输出统一映射为 `stop`，丢失驱动返回的 `stopReason: 'length'`；核心按正常返回将 Run 保存为 `completed`。网页、IM 和后台任务无法区分完整回答与达到输出限制的残缺回答。

**证据：**可控模型明确返回 `length`，最终运行仍为 `completed` 且 `error: null`；历史未留下截断状态。

**建议：**持久化真实结束原因，并在界面和其他入口表现为未完整生成；是否自动续写应制定明确策略，不能无条件将截断当成功。摘要路径已经检查结束原因，可参考其处理方式。

### 9. [P2] 插件发现误扫 pnpm 工具依赖并阻塞管理操作

位置：[apps/server/src/plugins.ts，第 6 行](../../apps/server/src/plugins.ts#L6)、[catalog.ts 的发现循环](../../packages/config-loader/src/catalog.ts#L57)、[manager.ts，第 435 行](../../packages/config-loader/src/manager.ts#L435)。

发现使用 CommonJS 的 `createRequire().resolve.paths()`，实际解析使用 ESM 的 `import.meta.resolve()`。pnpm 启动的 Vitest/tsx 会通过 `NODE_PATH` 引入工具自己的依赖目录和 `.pnpm/node_modules`，前者枚举这些目录，后者无法按同样范围解析，导致大量无用且串行的失败尝试。每次添加插件还会再次完整发现。

**证据：**直接 Node 的候选名称为 51 个，找到 33 个插件，单次扫描约 165 毫秒；pnpm/Vitest 中候选增加到 588 个，同样只找到 33 个插件，单次扫描约 2854 毫秒，其中 `resolveUrl()` 占约 98%。隐藏存储目录贡献 524 个额外名称。失败测试调用一次目录查询和两次添加，累计约 8 秒。将观察上限临时提高到 20 秒后断言通过、耗时 7.95 秒，证明是发现成本而非断言失败；默认 5 秒基线仍未通过。`pnpm exec tsx` 也存在相同目录注入，开发服务同样受影响。

**建议：**让发现目录与真实 ESM 解析范围一致，排除工具私有的 `NODE_PATH` 候选；枚举出的完整包名直接解析，添加操作校验目标包即可，避免重复扫描。保留确定性临时包树测试并增加真实 pnpm 启动回归，不以放宽超时替代修复。

建议继续收敛三处边界：

1. **HTTP 从核心分离。** [AI 的必需注入](../../plugins/definitions/ai/src/index.ts#L1086)与 [RBAC 的必需注入](../../plugins/definitions/rbac/src/index.ts#L1069)包含 Server。拆成可选 HTTP 子插件或独立适配器，让 IM/后台任务能够只装配所需能力。
2. **隐藏活动运行实现。** [AiService.running](../../plugins/definitions/ai/src/index.ts#L95) 是可变的 `Map<string, Running>`，im-ai、wake-tasks 直接读写相关运行对象。增加稳定的只读查询、可信内部取消与工具上下文验证接口，减少消费者依赖实现细节。
3. **空间目录由身份提供者扩展。** [RBAC.personalWorkspaces()](../../plugins/definitions/rbac/src/index.ts#L780) 显式识别 `@antarestra/plugin-auth-local`，其他 SSO/身份实现不能自然出现在文件管理空间目录。引入空间枚举契约比继续添加实现名分支更可维护。

## 第三方插件是否好用

**仓内扩展较好，独立生态尚未成形。** 有价值的基础包括统一 SDK、服务注入、可等待卸载、配置 Schema、自动发现、SFC 模板、共享 Vue/Reka UI 和生命周期插槽。工具、模型驱动与执行后端的注册接口也允许独立替换。

外部开发者主要会遇到这些障碍：

- SDK、定义包和其他工作区包均为 `private: true`，缺正式版本发布及发行文件契约。
- WebUI 模板使用 `workspace:*` 和仓内相对 tsconfig，不能直接复制到独立仓库构建。
- 需要同时理解 Node 条件导出、TypeScript 项目引用、server 安装范围、插件清单和 Cordis 注入；目前生成器没有覆盖完整外部安装链路。
- 核心服务与 HTTP/UI 的耦合增加最小插件宿主的搭建成本。
- 导入失败缺诊断、Schema 重载使用旧缓存，使第三方插件出错时难以自行定位。

建议先提供一个可发布的最小外部插件样板，并在 CI 中完成 SDK/定义包打包、独立项目安装构建、宿主安装发现、启停和卸载验收。明确 SDK 兼容范围及共享 Cordis/Vue 的依赖策略后，再考虑插件市场。当前无需为了市场重写已有插件模型。

## 其他安全与工程改进

以下为设计边界或改进建议，不计作已复现漏洞：

- **凭据保护。** 提供商 API Key 明文持久化是当前明确行为，API 遮罩不保护数据库和备份；可增加服务端密钥引用或带轮换机制的加密存储。本次核对的 OneBot、S3、网页搜索配置字段均为 `$变量名` 引用，没有把它们误报成硬编码密钥。
- **资源与费用额度。** 每会话串行和每 Run 模型调用上限不能限制同一用户创建大量会话并发调用。建议增加 Actor/Workspace 的并发、用量和队列额度，以及记忆、历史与事件保留策略。
- **持久化成本。** [全服务串行队列](../../plugins/definitions/ai/src/index.ts#L96)、[每次增量持久化](../../plugins/definitions/ai/src/runtime.ts#L467)和 [Run 整体保存](../../plugins/definitions/ai/src/index.ts#L992)会随长回复与多会话增加写入成本。建议按会话排队、批量写增量并使用检查点；本次未压测，不宣称已经测得容量上限。
- **关键操作审计。** 配置修改、权限调整、密钥变更、密码重置和后台任务需要可追踪的结构化记录，记录操作者、对象和结果，避免记录凭据或完整敏感输入。
- **前端体积。** 本次构建的页面壳入口约 835 kB、Markdown 入口约 715 kB，Markdown CSS 约 1.47 MB（均为未 gzip 产物）；建议检查图表、公式字体与共享组件的按需加载。这里只测得构建大小，没有浏览器加载性能结论。
- **生命周期兼容。** HMR 使用 Node 内部模块缓存与 Cordis 适配，当前封装集中是优点；升级 Node/Cordis/HMR 时需要单独的真实进程回归。
