# 引导 AI 会话实现与验证

## 行为

Agents 增加默认关闭的 `steeringEnabled`。启用后，网页和 IM 的运行中输入进入同一个 Run，按接收顺序在当前工具批次完整结束、下一次模型请求前插入；没有工具时在当前响应结束后继续。正在执行的工具不会被强制终止，工具调用与结果保持完整配对。运行快照固定开关、模型、工具及系统提示词。

引导消息独立持久化接收时间、发言者、原始输入和插入位置；幂等请求索引在 SQLite 重开后仍有效。收尾判断与接收共用串行锁。取消或异常保留已接收输入，不自动重放工具。网页气泡与普通用户消息相同，只在顶部显示小字“引导消息”。

IM 激活、动态概率、冷却和限频沿用原流程；通过激活判断后才尝试引导，原任务统一投递回复。目标运行恰好结束时回到普通队列。模板变量使用对应激活快照，私聊媒体限制仍按本空间、本次运行的有效输入校验。定时唤醒继续使用原有守卫和队列。

## 参考

- [Pi Agent 文档](https://github.com/badlogic/pi-mono/blob/main/packages/agent/README.md)：区分引导与后续排队，在请求边界消费输入；工具批次结果完整后继续。项目自身持有历史、权限和资源边界，因此在 AI 核心实现队列，不直接使用 Pi 的内部消息作为持久历史。
- [Codex 引导与排队说明](https://learn.chatgpt.com/docs/prompting)：引导改变当前任务，排队用于后续任务。本项目按 Agent 统一选择运行期间输入的行为。

## 实际验证

环境：macOS arm64，Node.js 24.22.1、pnpm 11.7.0。未运行全量测试，未验证 Windows 或 Linux；模型驱动为可控测试实现，不是外部真实模型验证。

- 明确限定 17 个相关测试文件，共 300 项通过：AI 核心、Agents、上下文、附件、生命周期，网页状态与处理展示，以及 IM 激活、历史、媒体、动态回复、状态、中间回复和控制台历史。
- 受影响的 `@antarestra/ai`、`@antarestra/plugin-im-ai`、`@antarestra/plugin-ai-agents`、`@antarestra/plugin-chat-webui` 构建通过；网页 Vue 类型检查与 `pnpm exec vue-tsc -p tsconfig.tests.json --noEmit` 通过。
- 重点新增用例覆盖工具结果顺序、多个引导输入去重、跨空间拒绝、无工具续写、关闭开关、卸载取消、最终响应竞态、SQLite 重开幂等、IM 不激活消息及不同群成员、自定义 `last_message` 模板、网页发送失败恢复与气泡展示。
- 浏览器检查 1280×800 常规窗口及 390×844 窄屏：运行中发送、历史刷新、普通用户气泡外观、开关键盘切换与保存；未出现浏览器控制台错误。
- 前端技能静态审计仍报告 5 处既有模式：Markdown 委托事件按钮、FloatingPanel 插槽触发按钮、Agents 的变量面板按钮及 Agents／配置面板通过样式表控制的文本框尺寸。此次未修改这些原有实现，不把该静态审计描述为通过；审计原始输出保存在本机 `/tmp/antarestra-steering-ui-audit.json`。技能目录未提供独立的设计文档检查脚本，设计文档使用项目格式检查并人工核对。
