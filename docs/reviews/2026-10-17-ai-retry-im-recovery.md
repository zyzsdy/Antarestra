# 模型请求重试与 IM 会话恢复

## 现场证据与原因

本机文件日志默认未开启，已有 `.local-dev` 日志为旧启动记录。本次只读查询当前 PostgreSQL 的 AI 运行记录和 IM 任务记录，未读取或输出模型凭据、用户消息正文。

- 2026-10-17 22:36:58（香港时间）运行 `347b0f6f-8825-4fa8-9497-fa1d0c91b2b7` 保存了 `provider_request_failed`，详情为 `sub2api API error (503): {"message":"Service temporarily unavailable","type":"api_error"}`，仅有一次模型请求。
- 对应 IM 任务为失败且已投递；同会话下一条任务也失败，但没有 `run_id`，已投递“AI 暂时无法处理此消息”提示。
- 2026-10-16 的图片过大 HTTP 400 后也出现多个没有 `run_id` 的失败任务，表明永久错误同样需要 IM 会话恢复。

AI 核心拒绝在未完成轮次后直接 `send`，避免把不完整工具结果与输出作为正常历史。Web 使用重新生成或切换完整节点恢复；IM 一直复用当前空间的会话发送普通 `send`，导致后续请求在创建 Run 前被拒绝。

503 是提供商返回的错误；以上证据不能进一步判断 sub2api 内部或其上游的具体故障原因。

## 修改

- `ai.maxModelRetries` 默认 2，支持 0–10 次额外重试。核心在单次模型请求层重试可识别的瞬时错误，Web、IM、直接模型与辅助模型调用共用。
- 从 1 秒开始指数退避，上限 30 秒；等待可取消并随依赖卸载回收。驱动显式关闭自身重试，避免叠加。
- 已输出内容或内置工具活动后不重放；鉴权、参数错误和输出截断直接结束。已完成的本地工具不重复执行。
- `im-ai.autoResetUnavailableConversation` 默认开启。下一条普通 IM 消息（含排队消息）在执行时替换不可用会话，保留历史，不重放旧消息；关闭时继续使用 `/reset`。
- IM 错误日志补充任务标识和已处理过的 AI 错误原因。
- 修复取消包装器的竞态：信号已取消但请求 Promise 已创建时，仍接管其拒绝，避免重试包装后在卸载期间产生未处理异常。

## 验证边界

先新增回归用例，确认旧实现遇到 503 仅调用一次。修复后覆盖重试成功、重试上限、关闭重试、取消和卸载、工具不重复执行、部分输出不重放、Web 失败节点和重新生成、IM 自动替换及关闭开关。

提供商测试使用真实本地 HTTP 服务返回 503 和 SSE，通过实际模型驱动与 AI 核心验证恢复；数据库集成测试使用真实 SQLite。现场 PostgreSQL 仅作只读诊断，没有向真实 IM 群发送测试消息，也没有通过付费上游执行模型测试。

本次相关的 7 个测试文件共 155 项通过，无未处理异常；全项目类型检查、格式检查、构建和编译产物启动冒烟检查通过。

全量默认并发执行并非全部通过：出现配置目录扫描超时、HMR 导入失败、Windows 短路径的 URL 编码差异，以及 3 个 IM 断言失败。通过 `.tmp/ai-retry` 中提取的 Git 基线源码对照，3 个 IM 断言（图片 `sub_type` 与两条提示词内容）在未修改 AI/IM 实现时同样失败。相关日志保留在本地，未把全量测试宣称为通过。

将临时目录改为不含 Windows 短路径的路径、限制为 2 个 worker 后，完整复跑为 1001 项通过、5 项失败、56 项跳过，无未处理异常；HMR 和 SFC 测试通过。剩余失败是上述 3 个既有 IM 断言、配置扫描 5 秒超时，以及覆盖配置文件重命名时的 `EPERM`。不能仅凭临时目录变化断定后两项失败的根因。

最后将两个配置测试文件恢复系统临时目录、限制为 1 个 worker 并允许 30 秒超时独立复查，56 项全部通过。未修改这些测试或对应业务代码，也未掩盖完整复跑中的失败记录。
