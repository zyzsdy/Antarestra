# 申请并接入飞书机器人

本项目使用企业自建应用机器人和官方 SDK 长连接。无需先安装飞书桌面客户端；可以先用网页注册/登录并完成开放平台操作。若已有组织，需获得该组织创建应用及审批权限；没有组织时先按飞书注册流程建立自己的组织。

## 创建应用

1. 打开 [飞书开放平台控制台](https://open.feishu.cn/app)，登录并选择目标组织。
2. 创建企业自建应用，填写名称、描述和图标。建议初期名称明确标注测试用途。
3. 在应用能力中添加并启用机器人。
4. 在凭证与基础信息中获取 App ID 和 App Secret。App Secret 只保存在本机被 Git 忽略的 `.env` 中，不放入聊天消息、截图、提交和日志。

## 申请消息权限

在权限管理中申请应用身份权限：

| 权限                               | 用途                                           |
| ---------------------------------- | ---------------------------------------------- |
| `im:message:send_as_bot`           | 以机器人身份发送消息                           |
| `im:message.p2p_msg:readonly`      | 读取用户发给机器人的私聊消息，仅启用私聊时申请 |
| `im:message.group_at_msg:readonly` | 接收群内 @机器人的消息                         |

权限名称以控制台当前展示为准，可按中文用途搜索。若希望处理不带 @ 的 `/ping`、固定命令或关键词触发，再申请接收群内全部消息所需的 `im:message.group_msg` 权限；仅有 @ 权限时，不带 @ 的群消息不会推送给系统，本地规则无法弥补平台未下发消息。

首版先用 @ 触发和测试群白名单即可。飞书端能接收到消息与 Antarestra 是否启用该聊天是两个独立条件。

后台任务恢复还需申请 `im:chat.members:read`，用来重新查询当前群成员，防止离群用户继续执行任务。如果需要回复重启前的历史消息，还需按「获取指定消息内容」接口申请相应读取消息权限；适配器必须先确认该消息属于目标聊天，无法验证时不会发送引用回复。后台恢复成员身份查询失败时也不会继续运行任务。飞书私聊成员查询的兼容性须在真实平台验收，当前不保证私聊后台任务恢复可用。

## 获取应用所属租户和机器人账号

配置还需要 `tenantId`（tenant_key）和 `botOpenId`（机器人的 open_id），它们不是 App ID。可在开放平台 API 调试台使用该应用身份调用 [获取机器人信息](https://open.feishu.cn/document/server-docs/bot-v3/bot-info/get)，读取机器人 open_id；tenant_key 可从组织信息、调试事件的租户字段获得。不要将用户自己的 open_id 填作机器人账号。

## 配置并建立长连接

本机 `.env` 增加：

```dotenv
ANTARESTRA_FEISHU_APP_SECRET=在此填入应用密钥
```

启用 `im`、`identity-im` 和 `im-console` 后，在主配置加入飞书接入实例。以下字段是示例，必须替换：

```yaml
im-feishu:
  id: feishu-test
  appId: cli_替换为应用ID
  appSecret: $ANTARESTRA_FEISHU_APP_SECRET
  tenantId: 替换为tenant_key
  botOpenId: ou_替换为机器人open_id
```

先保持所有聊天拒绝，启动 Antarestra 使应用建立长连接。然后在开放平台的「事件与回调」中选择「使用长连接接收事件」，保存并添加「接收消息 v2.0」事件 `im.message.receive_v1`。某些配置步骤会检查 SDK 已连接，遇到未连接提示先确认本机服务已启动、凭据正确且网络可访问飞书。

`appSecret` 与 `appSecretEnv` 二选一；后者只读取服务进程环境变量。项目 `.env` 文件通过配置加载器替换，应使用上例写法。

## 发布与测试

1. 在版本管理与发布中创建版本，将应用可用范围先限制到测试成员，提交管理员审批并完成发布。
2. 将机器人添加进测试群。通过开放平台调试台或事件调试确认目标 chat_id（通常以 `oc_` 开头）。私聊白名单同样使用平台 chat_id，不使用成员 open_id。
3. 在“机器人 → IM 接入”打开该连接的聊天规则，将测试群 chat_id 加入群聊白名单，保持私聊空白名单；保存后立即生效，无需重新加载插件配置。
4. 群内 @机器人发送 `/ping` 检查命令链，再配置 Agent 和 AI 激活规则进行 AI 测试。未安装命令处理插件时不会自动回复 `/ping`。
5. 检查其他群及私聊没有回复，并验证停用插件后长连接停止。

应用发布、审批、可用范围、机器人进群、消息权限、事件订阅及 Antarestra 白名单均需满足才能工作。飞书桌面客户端只是测试发消息的可选入口。
