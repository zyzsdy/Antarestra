# 即时消息基础服务

提供 `ctx.im`，依赖 `database`，由 `identity-im` 注册身份解析器。适配器和业务插件直接使用 Cordis 的 `inject`、`ctx.effect()` 与 Fiber 生命周期，不引入独立插件加载器。

## 接入与处理

适配器通过 `registerConnection(owner, descriptor)` 注册稳定接入标识、平台、机器人账号、可选租户、准入策略和发送能力。返回的 `receive()` 入口只接收已完成平台验签、账号校验的消息。平台 ID 一律用字符串。`setStatus()` 用于报告连接状态，不包含凭据。

`registerHandler(owner, { id, stage, handle })` 按 `command`、`message`、`ai` 顺序执行，返回 `consumed` 或 `rejected` 时停止后续处理。命令插件负责消费禁用、无权限或参数错误的已匹配命令；普通消息处理不要求 AI 开启。卸载处理器或连接时中止对应信号，并等待正在执行的处理器结束；业务处理器应响应 `context.signal`。

`MessageContext.request` 是保存在 WeakMap 中的进程内可信对象，可传给 RBAC 与 AI 的 `im` 请求来源。序列化、复制或自行构造同字段对象不能建立身份。异步排队后须重新执行授权；上下文不会因 `receive()` 返回失效，但连接、身份插件卸载，或成员、空间、准入策略撤销后不能再授权。

## 策略与空间

群聊和私聊分别设置 `whitelist` 或 `blacklist`；没有配置该类型即拒绝。生效值按实例默认、聊天类型默认、`chats["group:群号"]` 或 `chats["private:用户号"]` 合并。AI 默认关闭。适配器启动配置的准入名单作为上限，后台存储策略只能在该范围内启用聊天；扩大上限必须显式修改接入配置。

`getPolicy()` 返回已保存策略，`getPolicyRevision()` 返回修订号。`setPolicy(id, policy, expectedRevision)` 验证完整 JSON Schema 并在互斥区校验修订号，冲突抛出 `ImError`，状态码 `409`、代码 `revision_conflict`。`getChatPolicy()` 返回最终生效值，包含硬限制后的 `enabled`。

`send()` 与 `invoke()` 必须带连接、聊天对象和内部 Workspace ID，逐次核验持久化路由及准入范围。不能用另一个群的 Workspace 操作当前群。平台操作还需要匹配声明的能力；具体成员管理命令另外负责操作者权限检查。

引用回复还必须匹配该空间已登记的入站或出站消息 ID，未知引用会拒绝，避免平台按引用 ID 把消息发往另一个群。消息归属持久化，重启后仍可验证。

## 群聊发送延迟

在 `im` 插件配置中设置以下参数，也可通过插件配置面板的自动表单修改：

| 参数                        | 默认值 | 含义                                                    |
| --------------------------- | ------ | ------------------------------------------------------- |
| `sendDelayPerCharMs`        | `100`  | 每个文本字符延迟的毫秒数；设为 `0` 关闭全部发送延迟     |
| `longMessageThreshold`      | `100`  | 长消息字符阈值，严格超过此值才切换长消息字延迟          |
| `longMessageDelayPerCharMs` | `20`   | 长消息每个文本字符延迟的毫秒数；设为 `0` 则长消息不等待 |

延迟适用于所有通过 `ctx.im.send()` 发出的群聊消息（包括 AI 回复、命令回复），私聊不延迟。同一接入的同一群按顺序逐条等待并发送，前一条完成后才开始下一条的等待，不同群与不同接入互不阻塞。字数按解析后的文本 Unicode 码点计数，包含标点和空白，不含消息标签、提及 ID、引用 ID、图片地址等非文本片段；纯图片等无文本消息不额外等待。

默认配置下，10 个字等待 1000 毫秒；两条各 7 个字的消息先等待 700 毫秒发送第一条，再等待 700 毫秒发送第二条。100 个字等待 10000 毫秒，101 个字整条改用每字 20 毫秒，等待 2020 毫秒。

等待支持取消，卸载插件或接入、执行 `/stop` 或 `/reset` 时取消对应的待发回复。等待结束后重新校验准入与业务授权。延迟中尚未调用平台的消息不会记为发送结果未知；已成功投递的幂等键直接复用结果，不再次等待或发送。

## 可靠性边界

工作空间图片可使用 `resource://资源ID`。`registerImageResources(owner, resolver)` 注册空间内图片检查与临时 URL 解析能力，由 workspace-file 提供；注册随所属上下文回收，卸载取消并等待在途操作。ID 作为不透明标识保留大小写，特殊字符需百分号编码，引用本身不接受路径、查询参数或片段。

核心先验证发送目标与图片归属，排队和延迟结束后再生成临时 HTTP(S) URL。连接可通过 `prepareImage` 上传到平台取得图片键；OneBot 直接使用临时 URL。准备操作在 outbox 认领之前完成，准备失败可重试；真正发送后结果不明仍按未知投递处理。已发送的幂等结果不依赖原图片仍存在。内部图片的回复计划和归档保留资源引用，出站归档直接关联原文件，不再次下载和上传。

收件箱以接入实例、平台、租户、机器人账号、聊天类型、聊天 ID 和消息 ID 的摘要持久化去重。身份解析或验证未成功时不认领消息，可以重投；已认领后的业务失败保留失败状态，避免重放普通命令的不可逆副作用。准入群聊在命令消费或 AI 激活前保存完整消息；仍不自动恢复崩溃中的普通命令。AI 插件另行持久化其任务。

带 `idempotencyKey` 的发送记录持久化成功结果；同键成功投递不会重复调用平台。超时或中断无法证明消息未发送，返回 `delivery_unknown`，禁止自动重发同键。该行为不承诺平台恰好投递一次。

核心本身不调用模型，也不管理平台登录。平台连接令牌不得写入仓库。

## 群消息与媒体归档

保存文本、结构化内容、平台原始消息载荷、发送人 ID/昵称/角色、消息 ID、时间、聊天与连接标识、引用关系。机器人和被忽略用户的群消息也归档，但不触发命令或 AI；出站消息成功后归档。重复事件只产生一份记录。私聊不保存此归档，继续使用对应 AI 会话历史。

workspace-file 的可选 IM 扩展注册媒体存储能力。平台适配器负责经连接鉴权的媒体下载，文件服务复用空间配额、资源 ID、上传回收与物理对象垃圾队列。下载失败保留消息和媒体标识，后台每分钟重试。IM 服务配置 `mediaMaxRetries` 默认 `10`，表示首次保存失败后最多再重试 10 次（总共最多 11 次尝试），设为 `0` 则不重试。次数按每个媒体分别持久化，重启或插件重载不会重置；旧失败记录没有次数时按已尝试 1 次处理。达到上限后保留 `failed` 状态并退出自动重试队列，提高配置上限也不会自动重新入队。没有启用文件服务时保留待下载状态且不消耗次数，恢复后开始保存。平台资源已失效或超过文件服务的单文件上限时无法保存二进制，查询结果如实显示失败状态。

失败记录包含 `attempts` 和 `lastError`。重试期间输出警告，达到上限输出错误；日志包含连接、平台、空间、群、消息和媒体标识、媒体类型、尝试次数、已重试次数、上限及失败原因链。HTTP 下载错误包含状态码；原因摘要隐藏下载地址路径、查询参数与常见凭据，不输出原始请求、响应或连接配置。

清理仅针对带群归档来源标记的文件，移动文件不改变来源。默认按原消息时间保留 7 天；mediaRetentionDays 为 0 可关闭按时间清理。mediaMaxBytes 为 0 表示不限群媒体总大小，否则每个 workspace 超限时从最旧文件开始删除；两个条件可同时启用。配置在 IM 接入面板管理，定时清理约每分钟运行，接入离线时文件服务仍按最后保存的策略回收。文本、原始 ID 和媒体元数据不随文件删除，手动上传和私聊附件不受此规则影响。

服务端 history(workspaceId, query) 按空间查询并使用稳定序号分页，权限应由消费插件的可信请求或运行上下文提供。媒体存储扩展绑定所属插件 Context；卸载取消下载并等待在途操作。
