# IM AI 接入

插件包：`@antarestra/plugin-im-ai`。依赖 `im`、`imCommands`、`ai`、`database`，复用现有 AI 授权、Agent、上下文、运行与历史服务。

IM 核心负责白名单与身份。此插件只处理准入已通过且有效聊天策略中 `ai: true` 的消息。没有配置群激活条件时，仅 @ 当前机器人或 `/ai <消息>` 激活；私聊默认每条有效文本或媒体激活。媒体先下载到对应 workspace-file，再通过已有资源授权接口附给模型；不直接把平台外链当作 AI 附件。

`/stop`、`/reset` 的群聊/私聊名单与授权级别统一在 [im-commands](../im-commands/README.md) 的 `commands.stop`、`commands.reset` 配置。`/ai` 也可通过 `commands.ai` 集中限制（须匹配命令服务的前缀）；被拒绝时不进入 AI。此规则按首个单词匹配，不影响 @、关键词或其他非命令激活方式。

## 聊天策略

策略位于对应接入实例的 `policy`，按实例默认、群/私聊默认、指定聊天覆盖解析。例如：

```yaml
policy:
  private:
    mode: whitelist
    ids: []
  group:
    mode: whitelist
    ids: ['40894918']
    defaults:
      ai: true
      agentId: assistant
  chats:
    'group:40894918':
      queueLimit: 5
      activation:
        mode: any
        mention: true
        prefixes: ['/ai']
        cooldownMs: 1000
        maxPerMinute: 20
```

`activation` 支持 `always`、`mention`、`reply`、`prefixes`、`keywords`；`mode` 为 `any` 或 `all`。同类多个前缀、关键词内部采用任意匹配。回复激活信任适配器核实后的 `replyToBot` 或当前空间归档中已验证的机器人原消息，不会信任用户输入的引用文字。激活判定在本地完成，不调用模型。默认每空间每分钟最多接受 20 次激活，默认无冷却；可通过策略修改。

群消息由 IM 核心持久化，先归档再处理命令与 AI；AI 关闭时仍记录已准入的群消息。私聊不重复归档。旧 context、recentLimit 与 recentMaxAgeMs 配置已移除；数据库中已保存的旧策略会转换为模板和条数配置。新设置在“IM 接入”面板按接入、聊天类型或指定聊天继承。

- `{{history_message}}`：上次成功入队激活之后的未读群消息，包含本次触发消息，默认最多最近 50 条，可设 1–200 条。接收顺序游标与 AI 任务在同一事务中提交；重复投递、冷却和队列拒绝不会推进游标。重启可恢复；模型失败不会回退已接受的激活。
- `{{last_message}}`：本次触发消息，保留发言者、时间、原始消息 ID 和引用标记。
- `{{active_reason}}`：被 at、回复或引用机器人、命令、提到名字或关键词、动态激活、每条消息等实际命中的原因。
- `{{im_status}}`：当前工作空间最近保存的状态原文，没有状态时为空。执行请求时读取，因此排队请求可使用上一轮刚保存的状态；也可用于 Agent 的系统提示词和用户输入模板。

群聊默认输入为激活原因加未读消息，私聊默认为 last_message。仅发送当前消息时把 `userInputTemplate` 设为 `{{last_message}}`；这些变量也可直接用于 Agent 的用户输入模板。消息原文不作为模板递归展开。

每次请求默认最多附 5 张图片、5 个其他文件，可分别设为 0–20；合计仍受 AI 核心 20 个附件限制，单个文件最多 16 MiB。优先附最新媒体，并检查所选模型输入能力；过旧、过期、下载失败、超限或模型不支持的内容仍保留 `[图片,id]`、`[视频,id]`、`[音频,id]`、`[文件,id]`。附上的资源标为 `[图片（附件1）,id]` 等，编号对应实际附件数组。

`im_history_query` 工具只能查询当前可信运行的工作空间，支持带时区的 ISO 时间范围、发送人平台 ID、文本子串关键词和向前分页。返回原始消息 ID、发送人、时间、连接、聊天、媒体资源 ID 与存储状态。请在 Agent 的工具范围中允许此工具；模型不能传入其他 workspace。

## 群聊动态回复

控制台的“自定义 AI 激活条件”中可开启“动态回复”，也可配置 `activation.dynamic: {}` 使用默认值：

```yaml
activation:
  mention: true
  prefixes: ['/ai']
  dynamic:
    baseProbability: 0.002
    hotProbability: 0.2
    hotDurationMs: 120000
    maxSilentMessages: 150
```

动态条件与普通条件组合的结果采用“或”关系；普通条件之间仍遵循 `mode`。因此 @ 或前缀可以正常唤起机器人，动态回复也可以独立触发；“每条消息”已启用时，随机条件不再减少回复次数。动态条件仅适用于群聊，私聊继续遵循普通条件。

设基础概率为 b，热点初始概率为 h，热点窗口为 T，连续未激活的有效消息条数（含当前消息）为 n，保底阈值为 N：

- 热度 H = (exp(5 × (1 − t/T)) − 1) / (exp(5) − 1)，t 为距热点开始的时间；无热点或 t ≥ T 时 H = 0。
- 时间概率 B = b + max(0, h − b) × H。热点概率低于基础值时不会降低基础概率。
- 沉默压力 S = (exp(10 × min(n/N, 1)) − 1) / (exp(10) − 1)。
- 最终单条概率 P = B + (1 − B) × S；n ≥ N 时精确为 100%。每条有效消息独立抽样一次。

默认无热点时，第 30、75、120、135、150 条的单条概率约为 0.23%、0.87%、13.70%、36.91%、100%。这些是“此前一直未激活”的条件概率，不是累计概率或平均回复间隔；阈值 150 不表示通常等待 150 条。

成功入队即视为激活，沉默计数归零，但此时不开启热点。只有模型完成并生成通过完整预检的非空回复后才开启热点；热点窗口内再次回复不会续期，因此连续接话也会逐渐冷下来。模型自主选择空回复时不发送任何消息，并立即清除该空间已有热点，后续只使用基础概率与逐渐上升的沉默压力，即 P = b + (1 − b) × S。模型运行期间累计的消息计数会保留；下一次成功入队再归零，避免达到阈值后因持续空回复而每条都调用模型。

模型失败、取消或格式预检失败不会开启新热点，也不视为模型自主沉默；投递失败不改变已确定的回复选择，重试不重新升温。热点结束或被空回复清除后，下一次有效非空回复可开启新窗口。概率在本地计算，是否参与话题由模型结合聊天内容决定。

仅统计通过准入、AI 已启用、完成去重且到达 AI 阶段的有效群聊文本或媒体；普通命令、空消息、机器人消息和重复投递不计数。冷却、每分钟限流、队列容量仍优先，受阻的消息不清零计数、不启动热点；达到阈值后保留 100% 直到成功入队。主动发送、命令回复和平台消息投递均不读取或修改动态状态。

状态按 Workspace 隔离，IM 核心保证空间对应唯一接入账号和聊天；同群成员共享状态，不同群和账号互不影响。状态只保存在当前插件实例内存，卸载/重启重置；发现动态关闭或 AI 禁用时清理该空间状态。`/stop`、`/reset` 只处理运行和上下文，不改变动态概率。配置存储仍复用 IM 策略数据库及修订校验。

## 会话、运行与投递

### 分条回复格式

采用受限标签格式，外层 `<im_reply>` 明确区分结构化回复与普通文字。它便于书写多行自然语言，不要求模型为每一处换行和引号进行 JSON 转义；服务端只识别白名单标签，不执行 HTML，也不进行 XML 实体扩展。

```xml
<im_reply>
<message>我先说一下想法。</message>
<image>resource://图片资源ID</image>
<message quote="123456">你刚才提到的这点，我也赞同。</message>
<message><at id="79338528"></at> 想听听你的看法。</message>
<sticker>resource://表情包资源ID</sticker>
</im_reply>
```

示例中的用户 ID 和图片资源 ID 须替换为当前聊天的真实用户 ID 与当前空间的文件资源 ID。`message`、`image` 和 `sticker` 按顺序各发送一条消息，最多 20 条；都可携带唯一的 `quote="原始消息ID"`。引用必须是当前聊天已接收或发送过的真实消息，不能跨群、跨账号或跨空间。可以引用上下文或 `im_history_query` 返回的 `messageId`，不是发言者 ID 或内部归档 ID。

`message` 内可写文本并插入 `<at id="用户ID"></at>` 主动提及用户，支持与文本混排、连续提及多人、仅发送提及，以及与 `quote` 同时使用。`at` 转为原生提及消息段，与前后文本属于同一条消息，不占额外的分条数量；OneBot 发送 QQ `at`，飞书发送 `at user_id`。用户 ID 使用当前聊天上下文或 `im_history_query` 中真实发言者的 `id`（QQ 用户号或飞书用户 `open_id`），保留前导零，不使用昵称、消息 ID 或猜测的 ID。

仅允许在 `message` 内嵌入 `at`；`at` 必须为空且仅有一个非空 `id` 属性，ID 不含空白或控制字符且不超过 200 个字符。其他标签不允许嵌套；`image` 和 `sticker` 内为非空图片地址。不支持未知标签、任意属性及自动补全未闭合标签。

消息正文和图片地址中的链接、`&`、双引号和单引号可以直接原样输出，模型无需处理网页搜索结果中的 URL 参数分隔符。例如 `https://example.com/?a=1&b=2` 可直接放入 `message`，图片直链也适用。服务端兼容 `&amp;`、`&lt;`、`&gt;`、`&quot;`、`&apos;`，只解码一次；其他 `&` 序列（包括未知或数字实体）保持原文，不扩展外部实体。正文中的 `<`、`>` 仍需写为 `&lt;`、`&gt;`，转义后的 `at` 示例仍为普通文本。`quote`、`id` 属性保持严格实体校验，特殊字符仍使用上述五种实体转义；引用归属和图片协议、资源权限校验不变。

聊天与 AI 无关或 AI 不想回复时，可以输出 `<im_reply><message></message></im_reply>`，也支持整份回复简写为 `<message></message>`。空白 `message` 被忽略；整份回复没有非空内容时，任务正常完成，持久化空发送计划，IM 不发送消息或错误提示。纯空白最终正文同样保持沉默。空白标签与非空内容混用时仅发送非空内容，最多 20 个标签的限制仍包含空白标签；空图片、空表情包和空外层 `<im_reply></im_reply>` 仍为格式错误。

除空回复简写和下述状态块外，普通文本（包括用于展示代码的围栏）仍作为一条文本发送；`<im_reply>` 中的消息标签才进入结构化处理。整份围栏代码和消息中转义后的标签示例不作为状态指令。

图片与表情包优先使用 `resource://图片资源ID`，QQ 和飞书共用这一格式，资源 ID 保留大小写。启用 workspace-file，并在助理工具列表中允许 `im_prepare_image`；调用 `{ "resourceId": "ID" }` 或 `{ "path": "/图片.png" }`（二选一）检查图片后，把返回的 `src` 原样放入标签。工具只准备资源，最终回复才发送。图片须属于当前空间且仍存在，支持 PNG、JPEG、GIF、WebP，最多 8 MiB；不会因 ID 可见而获得其他空间的访问权。

发送计划仅保存资源引用，整份回复先检查图片与引用归属。同群排队与发送延迟结束后，文件服务向所属存储 provider 申请无需登录或额外请求头的临时 URL；恢复投递时重新生成，不把临时凭证保存在回复计划或内部图片的群消息归档中。OneBot 将地址交给 NapCat 下载；飞书由适配器下载并上传到平台取得图片键。签名或上传失败发生在认领消息投递之前，可以安全重试；消息投递结果未知时仍禁止自动重发。出站归档复用原资源，不重复上传或占用配额。

OneBot 仍支持已知 HTTP(S) 图片直链，拒绝本地路径、Base64 和带用户凭据的 URL；飞书仍支持已上传的 `feishu://image/资源键`，不接受模型直接提交任意 HTTP 图片地址。`sticker` 按图片发送，可发送 GIF，不表示平台原生表情或专属贴纸。旧任务保存的格式指引保持原快照，新任务使用更新后的指引。

`{{im_reply_format}}` 由 IM AI 插件持续注册，出现在 Agent 系统提示词任意位置时展开为指引，不受自动追加开关影响；普通网页等非 IM 运行中展开为空。模板变量目录同时提供说明，不解析真实运行内容。

“IM 接入 → 配置聊天规则 → 自动追加回复格式指引”对应 `appendReplyFormat`，支持继承、启用和关闭；系统默认关闭。按接入默认、群/私聊默认、指定聊天逐项覆盖。启用时在系统提示词末尾追加；系统模板已包含 `{{im_reply_format}}` 时不重复追加。开关与指引随本次输入在入队时固定，后续配置变更不改写已接受的请求。关闭自动追加只影响指引注入，结构化回复解析始终可用。

发送前完整解析所有消息，检查当前空间引用与适配器格式；格式错误只发送一条明确的失败提示，不先发送部分正文。原始回答仍保留在运行和任务历史中。解析后的发送计划持久化，每条消息复用 IM 发件箱的独立稳定幂等键；恢复时跳过已送达内容，不重新生成回答。逐条等待发送完成并重验授权；中途结果未知则停止后续投递且不自动重发。平台发送无法提供跨多条消息的原子性，已送达消息不会因后续失败撤回。

### 工作空间状态

模型可在最终回复中返回一个 `<status></status>`，例如：

```xml
<status>
心情: "开心"
状态: "正在闲聊"
记忆: ""
动作: "拿起手机聊天"
</status>
```

标签内部是模型自由产生的纯文本，不解析 YAML、JSON、字段或内部标签，也不限制字段名称和内容格式。服务端只提取 `<status>` 与第一个 `</status>` 之间的原文，保留换行、首尾空白、引号、实体和模板标记，不解码或递归展开。上面的字段只是示例；可直接使用自然语言记录状态。正文如果需要提及结束标签本身，应避免使用完整的 `</status>` 分隔符。

状态块可单独输出、放在普通正文或 `<im_reply>` 前后，或作为 `<im_reply>` 内与 `<message>` 同级的标签；不能放入发送消息标签内部，不接受外层属性、未闭合或多个状态块。状态不会作为 IM 消息发送、不占 20 条消息额度；只输出状态也会正常保存并保持沉默。

在 Agent 系统提示词、用户输入模板，或 IM 聊天规则的 `userInputTemplate` 中使用：

```text
当前聊天状态：
{{ im_status }}
```

变量只插入保存的内部原文，不包含 `<status>` 外层。模板解析使用可信运行的 workspace，不能通过输入变量指定其他空间；用户消息和状态原文中的 `{{...}}` 不再次展开。变量目录会自动提供 `im_status` 及其说明。

状态存储于 IM AI 插件数据库的 `statuses` 表，以 `workspace_id` 为主键。同群不同成员共享，不同群、私聊用户和接入账号各自独立。新状态整体替换旧状态；没有状态块时保留旧状态，`<status></status>` 保存空文本以清空状态。状态跨插件卸载、重启、切换 Agent 和 `/reset` 保留，与 AI 会话上下文及动态回复热度分开存储。

只有成功完成并通过整份回复预检的模型输出才更新状态。状态与发送计划在同一事务中保存；取消、模型失败或预检失败保留原状态。之后的投递失败不撤销状态，恢复旧发送计划也不会重写状态或覆盖较新的状态。

### 运行与恢复

一个 Workspace 持久化关联一个当前 AI Conversation，同群不同成员共享会话，但每次运行使用当前发言者的可信授权。输入保留发言者 ID 与名称，`UserInput.variables` 包含 `imActorId`、`imWorkspaceId`。同一空间串行，不同空间可并行，排队上限由 `queueLimit` 控制。普通命令不会等待模型完成。

更换 `agentId` 后在原 Workspace 新建会话，旧历史保留。`/reset` 取消当前 AI 与排队消息，在下次激活时建立新会话；群消息归档与已读游标保留；`/stop` 取消当前 AI 并清空排队。两者需要 `ai.chat.use` 权限，使用自定义命令前缀时随前缀变化。运行失败或取消后如当前会话未形成完整一轮，可用 `/reset` 重新开始。

入队消息、原始运行命令、运行 ID、最终回复和投递状态保存到插件自己的数据库命名空间。执行时重新检查身份、聊天策略与最新会话 revision，保存原始命令后才启动运行。同一消息恢复时继续使用原幂等键及参数，不重复调用模型。服务启动后会处理已上线连接的待恢复任务，后台授权要求适配器支持成员查询；离线连接等待恢复。

只发送最终助理正文，不发送思考、工具参数、工具结果或中途过程说明。发送目标始终携带连接、聊天和 Workspace。投递失败不重新生成答案；平台结果未知时标记 `unknown`，不自动重发。`deliveryAttempts` 只限制明确失败的重试；IM 核心的持久化发件记录继续约束重复发送。

插件卸载会停止定时检查、取消活动运行、等待清理并回收 `/stop`、`/reset`。持久化记录保留，普通命令与其他 IM 插件继续运行。定时唤醒可复用 IM 后台身份，但自动将唤醒任务结果推送到原群尚未实现，不能把后台身份支持等同于定时推送完成。

## 验证范围

相关集成测试使用真实 Cordis 与 SQLite 数据库、示例模型驱动，覆盖名单准入、命令独立运行、激活过滤、同群多人共享、双账号隔离、串行队列、取消、Agent 切换、消息幂等恢复、未知投递和卸载。状态测试另覆盖自由文本保真、群聊与私聊隔离、文件数据库关闭重开、空状态清除、队列模板读取及旧投递重试不覆盖新状态。示例驱动测试不是飞书或 QQ 真实模型验证。
