# AI 提供商接入

`@antarestra/plugin-ai-provider` 通过 pi-ai 注册提供商、模型及模型驱动到 `ctx.ai`。控制台的“AI 设置 → 提供商接入”管理连接和模型，默认配置已启用本插件。依赖 `database`、`ai`、`rbac`、`server`、`webui`，页面挂载在管理控制台。

## 配置与权限

提供商记录包含 ID、名称、备注、内置模板、接口格式、Base URL、API Key、自定义 Header、模型及修订号。提供商 ID 创建后不可修改。读取和写入 API 同时要求系统范围的 `admin.console.view` 与 `admin.ai.providers.manage`；后者默认授予 admin。普通 AI 用户只能通过 AI 目录读取提供商名称及模型能力。

记录存储于插件自有数据库命名空间，支持 SQLite、PostgreSQL、MySQL 的已有数据库适配。API Key 按当前需求明文持久化；响应不包含 `apiKey` 字段，只返回 `apiKeyPlaceholder`，前 3 位、后 4 位保留，其余遮罩。长度不超过 7 的密钥全部遮罩以避免暴露完整值。编辑输入框始终为空，脱敏值只用于 placeholder；留空保留原值，输入新值替换，拒绝将遮罩提交为新密钥。额外 Header 是管理员管理字段，保存后可编辑；不要在普通 AI 目录或 WebUI 公开清单中暴露它们。

模型配置包含模型 ID、显示名称、上下文、最大输出 Token、文本/图片输入、文本输出、工具调用和支持的思考强度。写入携带修订号，冲突返回 409，刷新后重新编辑。保存立即重新注册，按照 AI 注册表契约中断使用旧注册项的运行。插件卸载回收注册、取消并等待模型目录请求；数据库记录保留供恢复。

## 模型目录

接口配置以提供商为单位：只需设置“默认接口格式”和 Base URL，无需逐模型配置。普通提供商与自定义网关使用该默认配置；使用所选内置提供商的官方地址时，已知模型自动适配协议和端点，远端目录中的新模型优先沿用同系列且端点一致的内置模型配置，否则沿用提供商默认配置。不从其他内置提供商推断请求地址。

pi-ai 使用当前维护的 `@earendil-works/pi-ai` 包，旧 `@mariozechner/pi-ai` 已标记弃用。内置提供商与目录从 `providers/all` 读取，模型执行使用各 API 的懒加载实现，不维护进程级可变 pi 提供商注册表，也不引入 Agent 后端。

候选模型读取所选内置提供商的完整目录，不按提供商默认接口过滤；同 ID 跨接口重复时优先当前接口并去重。“获取模型列表”通过服务端请求对应 `/models` 接口，支持 OpenAI 兼容、OpenAI Responses、Anthropic、Google Generative AI 和 Mistral 的目录格式；其余接口明确提示仅支持内置目录与手动添加。目录请求包含保存的 API Key 和 Header，禁止跟随重定向，具备 30 秒超时、分页与响应大小限制。

同 ID 模型合并为一行。API 返回的模型始终按完整 ID 匹配 pi-ai 内置参数，优先所选提供商（同接口优先），其次其他提供商的相同接口，最后其他接口；自定义提供商也会匹配。命中后使用内置名称、上下文、输出上限、输入类型和思考能力，标记“内置 + API”，不会因此加入其他提供商未被 API 返回的模型。远端独有模型的缺失能力使用可编辑默认值：128000 上下文、65535 最大输出、文本和工具调用、无思考。同步前提示管理员核对；同步会新增所选或全部候选模型，并覆盖同 ID 模型的已保存配置；未参与同步的模型保持不变，手动添加模型也使用上述默认 Token 上限。远端失败保留内置目录并显示警告，不暴露远端错误正文或凭据。

## 当前边界

模型驱动支持文本、思考增量及工具调用。使用所选内置提供商的官方 Base URL 时，已保存的目录模型均由 pi-ai 内置提供商适配器发送请求；已知模型按 pi-ai 定义选择协议、端点及兼容参数，新模型若有端点一致的同系列模型则沿用其协议和端点。例如 opencode-go 的 Anthropic、Chat Completions 和 Responses 模型可共存，且会话 ID 由适配器用于请求路由。使用自定义网关地址时仍严格采用管理员配置的接口和地址，通过通用协议驱动发送请求，不将凭据转发到内置端点。模型的图片输入能力可以保存，但现有 AI 资源契约只有附件授权校验，没有资源内容读取，因此驱动会明确拒绝带资源附件的请求。OAuth 登录、云账号凭据流程及 Agent 执行后端不属于本插件；选择需要这些认证方式的提供商不会自动创建对应登录流程。

`tests/integration/ai-provider.test.ts` 覆盖鉴权、密钥边界、修订冲突、模型校验、SQLite 文件重启恢复、卸载和依赖恢复，以及本地 HTTP 模拟目录和 OpenAI 兼容流。模拟服务测试不代表外部真实模型集成验证。

模型返回的文本/思考续接签名随项目 DTO 持久化；下一轮只向同一连接、模型及驱动回传，避免思考模型的历史转换丢失协议字段。客户端不展示这些不透明字段。

## 提供商内置工具

在提供商详情的“提供商内置工具”区域添加工具，填写工具名、接口类型、可用模型、启用状态及 JSON 选项。类型由用户自由填写，`web_search`、`image_generation`、`file_search` 仅作为建议；例如文件搜索可以填写 `{"vector_store_ids":["vs_..."]}`。同一提供商的类型唯一，名称也唯一，避免提供方仅返回类型时无法确定对应配置。

Agent 工具列表用 `provider:提供商ID:工具名` 区分不同提供商的配置。允许全部工具的 Agent 自动包含新配置；指定工具列表的 Agent 需要显式勾选。调用仅在工具启用、当前模型匹配且 Agent 授权时生效，声明以 `{ type, ...options }` 追加到提供商请求中；工具名用于配置和展示，不写入不支持 name 字段的原生工具声明。

当前适配 OpenAI Responses、Azure OpenAI Responses 和 OpenAI Codex Responses 接口。工具由提供商内部执行，返回的 `类型_call` 输出项保存为独立的 `provider-tool` 内容，不进入客户端函数工具循环，也不发送 `function_call_output`。调用状态和原始结果经事件流及历史保存，取消时保留已收到的状态，图片生成结果可在工具详情中预览。网关、模型及工具类型是否可用由真实提供商决定；工具选项须符合该提供商接口。
