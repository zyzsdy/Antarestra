# AI 提供商接入

`@antarestra/plugin-ai-provider` 通过 pi-ai 注册提供商、模型及模型驱动到 `ctx.ai`。控制台的“AI 设置 → 提供商接入”管理连接和模型，默认配置已启用本插件。后台依赖 `database`、`ai`、`rbac`；HTTP 管理接口通过局部注入 `server` 注册，控制台页面通过局部注入 `webui` 注册。未加载、卸载或重载 WebUI 不影响后台服务及已有模型注册。AI 与 RBAC 核心目前仍依赖 Server，这一拆分不代表整个 AI 栈已支持无 HTTP 部署。

## 配置与权限

提供商记录包含 ID、名称、备注、内置模板、接口格式、Base URL、API Key、自定义 Header、模型及修订号。提供商 ID 创建后不可修改。读取和写入 API 同时要求系统范围的 `admin.console.view` 与 `admin.ai.providers.manage`；后者默认授予 admin。普通 AI 用户只能通过 AI 目录读取提供商名称及模型能力。

记录存储于插件自有数据库命名空间，支持 SQLite、PostgreSQL、MySQL 的已有数据库适配。API Key 按当前需求明文持久化；响应不包含 `apiKey` 字段，只返回 `apiKeyPlaceholder`，前 3 位、后 4 位保留，其余遮罩。长度不超过 7 的密钥全部遮罩以避免暴露完整值。编辑输入框始终为空，脱敏值只用于 placeholder；留空保留原值，输入新值替换，拒绝将遮罩提交为新密钥。额外 Header 是管理员管理字段，保存后可编辑；不要在普通 AI 目录或 WebUI 公开清单中暴露它们。

模型配置包含模型 ID、显示名称、上下文、最大输出 Token、文本/图片输入、文本输出、工具调用和支持的思考强度。写入携带修订号，冲突返回 409，刷新后重新编辑。保存立即重新注册，按照 AI 注册表契约中断使用旧注册项的运行。插件卸载回收注册、取消并等待模型目录请求；数据库记录保留供恢复。

## 模型目录

接口配置以提供商为单位：只需设置“默认接口格式”和 Base URL，无需逐模型配置。普通提供商与自定义网关使用该默认配置；使用所选内置提供商的官方地址时，已知模型自动适配协议和端点，远端目录中的新模型优先沿用同系列且端点一致的内置模型配置，否则沿用提供商默认配置。不从其他内置提供商推断请求地址。

pi-ai 使用当前维护的 `@earendil-works/pi-ai` 包，旧 `@mariozechner/pi-ai` 已标记弃用。内置提供商与目录从 `providers/all` 读取，模型执行使用各 API 的懒加载实现，不维护进程级可变 pi 提供商注册表，也不引入 Agent 后端。

模型请求中，pi-ai 默认的 `pi (<平台> <系统内核版本>; <架构>)` User-Agent 追加 `Anta/<根 package.json 的 version>`，例如 `pi (win32 10.0.26340; x64) Anta/0.1.0`。提供商自定义 `User-Agent`（请求头名称不区分大小写）完整覆盖默认值，不追加后缀；模型自带的 UA、Anthropic OAuth 的 `claude-cli`、AWS Bedrock SDK 和 `pi-messages` 等特殊 UA 保持原样。此规则仅作用于 pi-ai 模型请求，不改变目录同步和附件 Files API 的请求头。

候选模型读取所选内置提供商的完整目录，不按提供商默认接口过滤；同 ID 跨接口重复时优先当前接口并去重。“获取模型列表”通过服务端请求对应 `/models` 接口，支持 OpenAI 兼容、OpenAI Responses、Anthropic、Google Generative AI 和 Mistral 的目录格式；其余接口明确提示仅支持内置目录与手动添加。目录请求包含保存的 API Key 和 Header，禁止跟随重定向，具备 30 秒超时、分页与响应大小限制。

同 ID 模型合并为一行。API 返回的模型始终按完整 ID 匹配 pi-ai 内置参数，优先所选提供商（同接口优先），其次其他提供商的相同接口，最后其他接口；自定义提供商也会匹配。命中后使用内置名称、上下文、输出上限、输入类型和思考能力，标记“内置 + API”，不会因此加入其他提供商未被 API 返回的模型。远端独有模型的缺失能力使用可编辑默认值：128000 上下文、65535 最大输出、文本和工具调用、无思考。同步前提示管理员核对；同步会新增所选或全部候选模型，并覆盖同 ID 模型的已保存配置；未参与同步的模型保持不变，手动添加模型也使用上述默认 Token 上限。远端失败保留内置目录并显示警告，不暴露远端错误正文或凭据。

## 当前边界

模型驱动支持文本、思考增量及工具调用。使用所选内置提供商的官方 Base URL 时，已保存的目录模型均由 pi-ai 内置提供商适配器发送请求；已知模型按 pi-ai 定义选择协议、端点及兼容参数，新模型若有端点一致的同系列模型则沿用其协议和端点。例如 opencode-go 的 Anthropic、Chat Completions、Responses 和 Google 模型可共存，且会话 ID 由适配器用于请求路由。使用自定义网关地址时仍严格采用管理员配置的接口和地址，通过通用协议驱动发送请求，不将凭据转发到内置端点。

pi-ai 1.3.0 将 opencode-go 的内置地址更新为 `https://opencode.ai/inference/go`（部分协议使用 `/v1` 后缀）。已有配置若仍使用 `https://opencode.ai/zen/go`，需在提供商配置中更新地址并重新同步模型，才能继续使用内置适配器的自动协议选择；升级依赖不会改写已保存的地址。

图片与文件经 AI 资源解析器校验空间并读取内容。图片转换为模型输入；PDF、UTF-8 文本和其他文档按目标协议转换，OpenAI Responses 的部分二进制办公文档通过 Files API 上传。协议、模型能力或资源大小不支持时明确报错，不只检查附件引用。具体支持范围、远端清理及大小限制见[聊天附件](../chat-webui/README.md#图片与文件附件)。OAuth 登录、云账号凭据流程及 Agent 执行后端不属于本插件；选择需要这些认证方式的提供商不会自动创建对应登录流程。

附件 payload 转换仅递归处理数组和普通数据对象，保留 SDK 的 `AbortSignal` 等运行时对象。Google Generative AI、Vertex 以及 opencode-go 的 Gemini 模型均依赖这一约束；即使没有附件，也不能将请求取消信号复制成普通对象。`tests/integration/provider-google.test.ts` 使用真实 SDK 和本地 HTTP 模拟服务验证纯文本、PDF 流式响应及请求取消，覆盖 opencode-go 内置协议选择和会话请求头，不代表外部模型服务验证。

`tests/integration/ai-provider.test.ts` 覆盖鉴权、密钥边界、修订冲突、模型校验、SQLite 文件重启恢复、卸载和依赖恢复，以及本地 HTTP 模拟目录和 OpenAI 兼容流。模拟服务测试不代表外部真实模型集成验证。

模型返回的文本/思考续接签名随项目 DTO 持久化；下一轮只向同一连接、模型及驱动回传，避免思考模型的历史转换丢失协议字段。客户端不展示这些不透明字段。

## 提供商内置工具

在提供商详情的“提供商内置工具”区域添加工具，填写工具名、接口类型、可用模型、启用状态及 JSON 选项。类型由用户自由填写，`web_search`、`image_generation`、`file_search` 仅作为建议；例如文件搜索可以填写 `{"vector_store_ids":["vs_..."]}`。同一提供商的类型唯一，名称也唯一，避免提供方仅返回类型时无法确定对应配置。

每项工具可配置“每 5 小时调用上限”（`callsPer5Hours`），非负整数，默认及 `0` 表示不限制。按工作空间、提供商 ID 和工具类型独立统计，同一工作空间的多个会话、助理和模型共用额度；改工具名称不重置额度。计数保存在数据库，配置更新、热重载与重启不会清零。未限制时仍记录实际调用，之后启用限制会计入尚未过期的使用量。

额度表由 `002_builtin_usage` 创建，查询索引由后续的 `003_builtin_usage_indexes` 创建。开发服务可能在 Git 提交前通过热重载执行迁移，因此已执行的迁移定义同样不可修改；后续结构调整必须追加迁移，不能改写历史校验和或删除已有额度表。

请求前在本地为每个受限工具原子预占一次额度，避免并发请求重复使用最后一份额度，不再预占整个剩余额度。完整响应后按唯一调用 ID 结算，重复流事件不会重复扣除，没有调用的预占会释放；失败调用也计入次数。取消、断线或进程崩溃时无法确认提供商是否已经执行，保守保留预占 5 小时，已返回的多次调用仍全部计数。完整请求按结算时间保留 5 小时，避免长请求提前释放。当前由单个提供商服务实例串行协调预占，不承诺多个服务进程共享数据库时的分布式限流。

限制完全在本地执行，不向上游发送 `max_tool_calls` 或调用额度字段。请求前额度耗尽时移除该工具的原生声明，并在模型系统上下文中明确加入“内置工具 工具名：本工具已用完5小时调用限制”，模型仍可继续文字回复或使用其他工具。这不是客户端函数工具错误返回：提供商内置工具不支持客户端插入 `function_call_output`。同一上游响应内部可能执行多次工具调用，本地在收到结果后全部计数，并在下一次请求时移除已达上限的工具；不能撤回已经发出的请求或阻止提供商在该响应内部继续调用。

`image_generation` 完成后，AI 核心将 PNG、JPEG 或 WebP 产物保存为当前运行所属工作空间的附件，再将文件 `resourceId`、类型、大小和尺寸反馈给模型并自动续轮。网页聊天与 IM 共用此流程；网页可引用文件内容地址，IM 按会话回复规范使用 `resource://文件ID`。内置工具仍在提供商执行，不转换为客户端函数工具。需要启用工作空间文件服务及其可写存储，沿用空间授权、配额与单张图片 8 MiB 限制；保存失败会使运行失败。重复流事件按调用 ID 去重，运行记录与后续模型文本上下文不保存图片 Base64。自动续轮沿用模型调用上限、取消和依赖卸载机制。

Agent 工具列表用 `provider:提供商ID:工具名` 区分不同提供商的配置。允许全部工具的 Agent 自动包含新配置；指定工具列表的 Agent 需要显式勾选。调用仅在工具启用、当前模型匹配且 Agent 授权时生效，声明以 `{ type, ...options }` 追加到提供商请求中；工具名用于配置和展示，不写入不支持 name 字段的原生工具声明。

当前适配 OpenAI Responses、Azure OpenAI Responses 和 OpenAI Codex Responses 接口。工具由提供商内部执行，返回的 `类型_call` 输出项保存为独立的 `provider-tool` 内容，不进入客户端函数工具循环，也不发送 `function_call_output`。调用状态和原始结果经事件流及历史保存，取消时保留已收到的状态，图片生成结果可在工具详情中预览。网关、模型及工具类型是否可用由真实提供商决定；工具选项须符合该提供商接口。
