# 飞书接入

使用官方 `@larksuiteoapi/node-sdk` 的企业自建应用长连接。不需要本机安装飞书桌面软件，也不需要公网 HTTP 回调地址；创建应用和审批仍需飞书账号与组织权限。

申请、权限和配置步骤见 [飞书机器人接入指南](../../../docs/飞书机器人接入.md)。

每份连接使用独立应用凭据、SDK 客户端与 HTTP 实例，空间标识包含接入实例、租户、应用和机器人账号。只接受配置应用与租户下的人类消息，忽略机器人回声。准入规则默认拒绝全部聊天；入口和出口同时受接入配置白名单约束。

支持文本、@、引用、图片和文件资源键；飞书图片/文件记录为 `feishu://image/<image_key>` 和 `feishu://file/<file_key>`，并非公网下载地址。发送媒体要求已经上传到飞书的资源键且单独发送；尚不自动上传外部 URL 或下载入站附件到工作空间，也不支持富文本 post、卡片交互和飞书群成员管理。能力列表明确区分 `image.key` / `file.key`。

发送通过原 chat_id 或引用 message_id，带稳定请求 UUID；HTTP 请求设置超时并支持取消。SDK 收到事件后立即把消息交给 IM 核心异步处理，确认事件不等待模型。尚不把 SDK 事件确认等同于数据库持久化成功；进程在确认后、核心写入前意外退出可能丢失该事件。卸载取消 HTTP、关闭 SDK 长连接与重连计时器，并等待已启动的 HTTP/初始化任务退出。

引用发送必须核对原消息的 chat_id；本次运行内已见过的消息使用有界映射，其余消息通过平台查询验证，不允许用其他聊天的 message_id 绕过白名单。后台任务恢复会分页查询当前聊天成员列表，要求 `im:chat.members:read` 权限；离群、查询失败、权限不足或平台不支持该聊天类型时均拒绝恢复，不把旧消息发送者视为永远有效。飞书私聊的成员查询尚未经真实平台验证，若 API 不接受该聊天类型，该私聊的后台任务会被安全拒绝；实时消息仍按可信事件身份处理。所有查询所得成员目前只赋予普通成员角色。

当前自动测试模拟官方 SDK 边界，覆盖租户/应用隔离、白名单、消息结构、发送、成员查询和卸载；没有飞书真实账号时不能视为真实飞书接入验收。
